# 0.9.11 启动版本检查（工坊已提交）

正式版与测试版分别构建，不合并游戏 API。启动入口在 NoInlining 的玩法初始化方法之前检查 release_info.json，按各自编译目标精确匹配0.107.1 / 0.111.0。匹配版本正常初始化；错装时只排队一个 Godot 原生提示，然后向原生模组加载器报告受控初始化失败，避免继续注册玩法。

提示列出当前游戏版本、所需游戏版本、模组版本，要求退出游戏、取消订阅后重新订阅并等待下载。若仍不匹配，提示更换正确游戏分支/模组包。中文、英文、系统字体回退；本地化组件缺失时仍能显示。原版还可能显示自身的模组加载失败提示。

最低版本清单保持0.107.1只是为了让两个已支持版本都能运行启动检查；不代表测试版玩法支持正式版。实际玩法目标由二进制常量、build-target.txt及发布范围决定，发布校验必须核对这些，不能仅看min_game_version。最低版本以下如被原版预先拒绝加载，仍使用原版错误提示。

测试：两个目标分别编译；匹配/错配/未来版本/缺失或损坏元数据；原生AcceptDialog中英文显示、确认释放及单次提示；加载两种错误目标程序集并调用真实Entry.Initialize，确认在Ritsu及玩法初始化前受控失败且弹窗可见。稳定版同步回归也通过。测试期间检测到环境再次切至正式版，后续按当前环境继续验证，未强行改变该分支选择。
